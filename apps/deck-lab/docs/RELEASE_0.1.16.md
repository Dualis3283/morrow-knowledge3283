# Deck Lab 0.1.16 — Necroduality and provenance-linked token copies

## Context and rules evidence

The user's Necroduality could not automatically resolve onto the battlefield and did not make a token when a nontoken Zombie entered (including manual placement). Its Oracle text: "Whenever a nontoken Zombie enters the battlefield under your control, create a token that's a copy of that creature." Its published 2025-01-24 rulings say the token copies printed/copiable characteristics, not tap state, counters, Auras, Equipment or non-copyable effects; the copy's ETB abilities can trigger, as-enters and enters-with choices also apply. Source: https://mtg.wtf/card/vow/362/Necroduality and https://blogs.magicjudges.org/rules/comprehensive-rules/.

## Implementation and audit trail

1. **Cast and resolve Necroduality:** It is a named, castable `{3}{U}` enchantment with `partial` ability coverage, not an unsupported manually placed card. The normal shared mana planner pays its cost and the existing Resolve action puts it on the battlefield. Its supported trigger is not treated as a universal Oracle interpreter.
2. **Real stack trigger:** Every **nontoken Zombie** entering under Necroduality's controller through a normal spell cast, copy-adjudicated return or manual zone move adds one **separate trigger per Necroduality source** to the LIFO stack. There is no token until the trigger resolves. It may be countered with Stifle/Disallow; the entering Zombie stays put. The trigger holds a safe snapshot of the creature card's copiable attributes, original instance ID, Necroduality ID and controller; it still resolves if either source or entering creature leaves the battlefield before resolution. A Zombie token entering does **not** retrigger Necroduality.
3. **Reusable manual token-copy action:** `act(state,{type:'createTokenCopy',targetId,sourceId?,player:0|1,count:1..20})` accepts a **permanent currently on the battlefield**, an optional real linked source permanent/spell, a controller, and a requested number. It creates token copies of copied card characteristics, with **unique instance IDs, `isToken:true`, `copiedFrom:{id,name}`, and `createdBy:{sourceId,sourceName,mode}`**, fresh counters, damage and tap state. It goes through the regular battlefield-entry hook so other supported ETB interactions can fire; it cannot recursively fire Necroduality's **nontoken-only** trigger. This is an explicitly logged manual adjudication, not a fabricated source Oracle effect.
4. **Readable inspector:** All battlefield card inspectors have expandable **Create token copy…** with target permanent selection, optional source, token controller, and count. A Necroduality source defaults to itself. The created copies are labelled `TOKEN`, show "copy of" and "created by" provenance, and let users inspect a still-present source. Identifiers and records survive save/reload; the token ceases to exist after leaving the battlefield.
5. **Further precision:** Copies of commanders are **not** marked as commanders, and do not inherit counters/tap/damage. Printed mana cost and mana value remain. Manual copy of a token is supported. Type-specific copy modifiers, cloned DFC face, enter-with counters, as-enters choices, attachment mechanics and legend-rule interactions still require explicit manual adjudication; warnings are logged for suspicious printed entry effects.

## Test gates / evidence

12 new deterministic engine cases: Necroduality normal paid casting and resolution; trigger on manual entry; no creation until stack resolution; token/non-Zombie exclusions; two separate Necrodualities; last-known snapshot after source leaves; manually source-linked copy (including artifact), token copy without source, copied state/command flags, rejected invalid inputs, Stifle countering trigger, save/reload, tokens leaving play. 200 engine tests pass locally. A Playwright website regression at mobile touch 390px and desktop 1440px covers paid Necroduality casting, Zombie casting, pending trigger save/reload, copy after trigger resolution, manual source-linked copies, displayed provenance and persistence. CI, Android debug binary parity, packaging, merge, Cloudflare production and HTTP/hash readback are separate gates and must not be claimed before observed.

## Current limits / next steps

A named Necroduality trigger and general **manual copy of an existing permanent** are supported. Other ETB/cast copy effects (Reflections of Littjara, Parallel Lives, Adrix and Nev, Panharmonicon, alternate-copy modifications) need their own named effect adapters; never infer them automatically from descriptive Oracle text. Some ETB-as-copy effects, timestamp/copiable-value layers, modified characteristics, planeswalker/legend rule, copied DFCs and simultaneous ETB/APNAP ordering are not modeled. Physical Android device installation not observed. Practice game results are not authoritative MTG rules arbitration.

## Token and emblem rules

### Token accuracy gate

**creating card → exact token definition → name → color → type → P/T → abilities → visual proof**

The creating effect is authoritative.

Borderless design must explicitly carry characteristics that the normal frame would otherwise communicate.

### Emblems

Emblems are:
- symbolic / sigil-based;
- visually distinct from normal cards/tokens;
- mechanically sourced from authoritative text;
- allowed to share world language without sharing card layout.

## Print production

Locked geometry:
- trim: **63.5 × 88.9 mm**
- bleed: **3 mm each edge**
- cutter radius: **3 mm**
- artwork extends through bleed
- corners are cut physically rather than pre-clipped

### Print Master v1 — superseded

Defect: duplicated/overlapping token text because already-typeset token images received a second production text layer.

### Print Master v2 — canonical digital master

Correction:
- approved token faces used directly;
- duplicate overlay removed;
- only genuinely missing characteristics added;
- corrected emblem designs retained.

## Critical distinction

**digital print-ready ≠ physically print-approved**

Physical proof should inspect:
- trim tolerance;
- bleed;
- corner cutting;
- duplex registration;
- smallest rules text;
- token labels;
- emblem legibility;
- black-oil shadow separation;
- porcelain highlight retention;
- printer/stock behaviour.

A physical defect triggers a targeted production correction, not an automatic redesign reopening.

## Reusable lessons

1. Approval freezes an asset.
2. Retrieve canonical references instead of recreating from memory.
3. Environmental continuity is a fixed layer.
4. Art and rules/mechanics have separate authority.
5. Mechanically sensitive pieces are proven individually.
6. Token characteristics come from the creating effect.
7. Visual approval and mechanical approval are separate gates.
8. Print manifests must resolve to final canonical assets.
9. Render final production outputs; source logic alone is insufficient.
10. Different object classes can share a world without sharing a layout.
11. A website should curate rather than reproduce an archive.
12. Early success proves the idea; refinement makes it coherent.
